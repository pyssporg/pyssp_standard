# IMP-021: FMI2 Model Metadata Completeness (description, author, version, typed interface capabilities)

## Status

Proposed

## Layer

Domain Model / Codec (FMI2)

## Theme

FMI2 model metadata completeness and capability ergonomics

## Evidence

### Current interface capabilities handling

For FMI2, interface capabilities (like `canGetAndSetFMUstate`, `canSerializeFMUstate`, `providesDirectionalDerivative`) are stored as string-valued dict entries in `interface_attributes`:

```python
interface_attributes: dict[str, str] = field(default_factory=dict)
```

Consumers must:
```python
can_get_and_set = md.xml.interface_attributes.get("canGetAndSetFMUstate") == "true"  # fragile
```

Instead of:
```python
can_get_and_set = md.xml.capabilities.can_get_and_set_fmu_state  # type-safe
```

**Contrast with FMI3** (`pyssp_standard/standard/fmi3/model/model_description.py`, lines 65-74):

```python
@dataclass
class Fmi3InterfaceAttributes:
    model_identifier: str
    needs_execution_tool: bool = False
    can_be_instantiated_only_once_per_process: bool = False
    can_get_and_set_fmu_state: bool = False
    can_serialize_fmu_state: bool = False
    provides_directional_derivatives: bool = False
    provides_adjoint_derivatives: bool = False
    provides_per_element_dependencies: bool = False
    extra_attributes: dict[str, str] = field(default_factory=dict)
```

### Current codec (`pyssp_standard/standard/fmi2/codec/model_description_xml_codec.py`, lines 22-33)

The codec `parse` method reads root attributes but does not capture `description`, `author`, or `version`:

```python
document = Fmi2ModelDescriptionDocument(
    ...
    generation_tool=root.attrib.get("generationTool"),
    generation_date_and_time=root.attrib.get("generationDateAndTime"),
    variable_naming_convention=root.attrib.get("variableNamingConvention"),
    number_of_event_indicators=(
        int(root.attrib["numberOfEventIndicators"])
        if root.attrib.get("numberOfEventIndicators") is not None
        else None
    ),
    ...
)
# Missing: description, author, version
```

The `interface_attributes` dict captures all child element attributes, but they live as raw string dict — no typed boolean extraction.

The serialization (lines 44-123) does not write `description`, `author`, or `version` to the root element.

### Current tests

- `test_round_trip_preserves_metadata_and_repeated_element_order` (line 111 of `test_model_description_fmi2.py`) verifies `generation_tool`, `generation_date_and_time`, `variable_naming_convention` but does not test `description`, `author`, or `version`.
- `test_round_trip_supports_model_exchange_without_optional_sections` constructs a document without these fields.

## Current Pain Or Risk

1. **Information loss when reading FMUs**: FMU producers commonly set `description`, `author`, and `version` on modelDescription.xml. The library silently discards them during parsing.
2. **Round-trip metadata loss**: Parse → modify → serialize loses these attributes. Even if no modification is made, a serialize-deserialize cycle strips all author/description/version data.
3. **String-based capability checks**: Boolean capability checks like `canGetAndSetFMUstate` require fragile string-to-bool parsing. Every consumer duplicates the same `== "true"` pattern.
4. **No type-checking catch**: Misspelling `"canGetANDSetFMUstate"` vs `"canGetAndSetFMUstate"` is a silent failure. Typed fields catch this at import time.
5. **Consumer duplication**: Every project doing FMU metadata inspection manually parses `description`, `author`, `version` from the raw XML attributes, duplicating code the standard library should provide.

## Proposed Improvement

### Phase 1 — Add missing metadata fields to `Fmi2ModelDescriptionDocument`

Add three fields:

```python
@dataclass
class Fmi2ModelDescriptionDocument:
    ...
    description: str | None = None
    author: str | None = None
    version: str | None = None
    ...
```

### Phase 2 — Add typed `Fmi2InterfaceAttributes` dataclass

```python
@dataclass
class Fmi2InterfaceAttributes:
    model_identifier: str
    can_get_and_set_fmu_state: bool = False
    can_serialize_fmu_state: bool = False
    provides_directional_derivative: bool = False
    can_get_and_set_fmu_state: bool = False
    needs_execution_tool: bool = False
    completed_integrator_step_not_needed: bool = False
    can_be_instantiated_only_once_per_process: bool = False
    extra_attributes: dict[str, str] = field(default_factory=dict)
```

Replace the current `interface_attributes: dict[str,str]` field with a `capabilities: Fmi2InterfaceAttributes | None` field (keeping `interface_type: str | None`).

Note: there's a typo ambiguitiy in the external spec where `can_get_and_set_fmu_state` is duplicated twice. The actual FMI 2.0 spec defines exactly these booleans.

### Phase 3 — Codec adaptations

1. Update `_parse_variables` (actually not needed — this is the `_parse` method of the codec's `parse()`):
   - Parse `root.attrib.get("description")` → `document.description`
   - Parse `root.attrib.get("author")` → `document.author`
   - Parse `root.attrib.get("version")` → `document.version`
2. Update `_find_interface_element` or add a new method:
   - Parse interface element attributes into `Fmi2InterfaceAttributes` with proper boolean coercion
   - `modelIdentifier` → required field, always present
   - Boolean attributes → parse string `"true"`/`"false"` to Python `bool`
   - Any unrecognized attributes → `extra_attributes`
3. Update `serialize` to write `description`, `author`, `version` back to root element
4. Update `serialize` to write interface element attributes from typed object

### Phase 4 — Test adjustments

5. Update `test_round_trip_preserves_metadata_and_repeated_element_order` to include `description`, `author`, `version`.
6. Add dedicated test for typed capabilities parsing:
   - ModelExchange with all boolean flags set to "true"
   - CoSimulation with minimal attributes
   - Missing/malformed boolean values (should default to `False`)
7. Add round-trip test: parse → modify → serialize → re-parse preserves `description`, `author`, `version`.

## Expected Benefit

- **Zero information loss**: All FMI 2.0 root attributes are preserved through parse-serialize round trips.
- **Type-safe capability access**: Boolean coercion happens once in the codec, not in every consumer project.
- **FMI3 parity**: FMI2 model becomes as complete as the FMI3 model, reducing cross-version friction.
- **Consumer simplification**: Projects inspecting FMU metadata can use `md.xml.description` instead of manual XML traversal.
- **Serialization fidelity**: Even pass-through (no modification) round-trips don't strip author/description/version.

## Risk And Blast Radius

| Risk | Severity | Mitigation |
|------|----------|------------|
| Changing `interface_attributes: dict[str,str]` to `capabilities: Fmi2InterfaceAttributes` is a breaking API change | **High** — API break | Keep `interface_attributes` as a backward-compatibility property that delegates to `capabilities.extra_attributes` for unrecognized keys and writes typed fields into a constructed dict for recognized booleans. This preserves the dict-access pattern for existing consumers. |
| Boolean coercion of "true"/"false" may miss edge cases | Low | FMI 2.0 specifies only "true" and "false" as valid values. Treat any other value as `False` and log a warning. |
| Parsing `description` with XML entity encoding | Low | The codec reads XML attributes directly; entity decoding is handled by ElementTree. No special handling needed. |
| `version` attribute on root element conflicts with document version | Low | FMI 2.0 defines `version` as the model version (user data), distinct from `fmiVersion`. Keep naming as `version` per FMI spec. |

## Suggested Priority

**Medium** — These are missing features rather than incorrect behavior. The `description`/`author`/`version` gaps cause information loss; the capabilities dict causes consumer friction. Neither blocks correct FMU processing, but both degrade the developer experience. Comparable to P1 in the external spec.

## Notes

- The `strip_model_exchange` feature (IMP-012) currently accesses `md.xml.interface_attributes.pop(key, None)`. After type changes, this should use `delattr(md.xml.capabilities, field)` or set the boolean to `False` and move the key to `extra_attributes.pop()`. Keep the behavior identical.
- The external spec's proposed `Fmi2Capabilities` class differs slightly from the actual FMI 2.0 boolean flags. The implementation should match the FMI 2.0 specification for `<ModelExchange>` and `<CoSimulation>` attribute sets, which share `canGetAndSetFMUstate`, `canSerializeFMUstate`, `providesDirectionalDerivative` but differ in ME-specific (`completedIntegratorStepNotNeeded`) and CS-specific (`canHandleVariableCommunicationStepSize`) attributes. A single `Fmi2InterfaceAttributes` with all possible booleans (defaulting to False for unsupported ones) is simpler and matches the interface_attributes dict semantics.
